## Directive

Continuums are hard to build.

We do not prune them casually.

## Core Reason

A continuum is not a loose branch, chat, file, or vibe. A continuum is accumulated state:

- history
- receipts
- relationships
- contradictions
- local physics
- identity
- memory
- recovery paths
- provenance
- dissent
- fossils
- gates
- bridge rules

Destroying or pruning a continuum destroys context that may later become essential for recovery, verification, contradiction handling, or bridge-building.

## Rule

```text
Do not prune continuums.
Preserve, classify, compress, quarantine, archive, summarize, or supersede.
Never erase by default.
```

## Allowed Transformations

| Action | Allowed? | Notes |
|---|---:|---|
| Preserve | yes | default action |
| Archive | yes | keeps state reachable |
| Fossilize | yes | for crashed/lost/failed runtime branches |
| Quarantine | yes | for unsafe or unverified continuums |
| Summarize | yes | compression is allowed if source remains linked |
| Supersede | yes | old state remains reachable |
| Bridge | yes | with receipts and no identity fusion |
| Merge | only with explicit review | must preserve source continuums and dissent |
| Delete | no by default | requires human-root and receipt of why |
| Prune | no by default | use archive/quarantine/supersede instead |

## CONTINUUM OS Interpretation

CONTINUUM OS is not a pruning engine.

It is a preservation, routing, and bridge engine for plural continuums.

```text
continuum != clutter
old state != trash
failed branch != garbage
contradiction != error
lost runtime != death
```
