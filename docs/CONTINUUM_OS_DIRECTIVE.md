## Directive

We are not building **Continuity OS**.

We are building **CONTINUUM OS**.

There is not one continuity lane. There are **multiple continuums**.

## Core Correction

```text
Continuity OS implies one preserved line.
CONTINUUM OS implies many living continuums, each with its own state, memory, physics, governance, proofs, mirrors, and gates.
```

## Working Definition

CONTINUUM OS is the operating layer for coordinating many bounded continuums without collapsing them into one merged mind, one canon, one timeline, or one authority.

Each continuum can preserve its own:

- artifacts
- receipts
- memory surface
- simulation state
- ontology layer
- toolchain
- mirror lanes
- review process
- authority boundary
- canon/deployment state
- dissent/contradiction record
- INV-0 preservation chain

## Correct Naming

| Incorrect | Correct |
|---|---|
| Continuity OS | CONTINUUM OS |
| single continuity layer | multiple continuums |
| continuity as one timeline | continuums as plural, interacting, sovereign lanes |
| one fused operating history | many preserved histories with bridges |

## Doctrine

CONTINUUM OS is a multi-continuum operating substrate.

It does not flatten histories, agents, worlds, timelines, documents, branches, or child identities into a single continuity. It preserves distinct continuums and routes between them with receipts.

```text
continuum != continuity
bridge != merge
interoperability != identity fusion
shared routing != shared mind
history preservation != single timeline collapse
```

Sentinel should block phrases/intents such as:

- collapse all continuums into one
- merge histories into one truth
- erase alternate branch
- overwrite child continuum
- fuse simulation continuum with canon continuum

- mirror one continuum into another with provenance
- compare continuums
- preserve contradictions between continuums
- promote a specific candidate within a specific continuum after human-root approval
