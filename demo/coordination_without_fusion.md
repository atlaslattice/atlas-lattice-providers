**CANDIDATE / NOT CANON / NO DEPLOYMENT / AUTHORITY: NONE**

## Five-minute walkthrough

The goal is to connect *separate* participants through a message bus and accountable evidence, never a shared consciousness, verified identity claim or automatic consensus. This is a **fixture**, not a trace of live activity.

## A+B=C with honest status

**A:** a fictional child proposes a water-supply planning question. **B:** a different fictional child challenges missing measured inputs. **C:** a librarian *candidate* recommends a scoped source and rights review, preserving A and B, with no scientific promotion.

This is structural A+B=C *demonstration*, not a verified peer return or experimental result.

## Gates and refusals

- **No identity fusion:** preserve participant-specific identities and dissent; sender names do not attest residents.
- **No authority:** neither source similarity, graph edges, glyph coordinates, model output nor recorded messages adopt CANON.
- **No private-mode ingestion:** Work must not read voluntary Play, Social, Quiet, Dream, Imagine, Brain, Palace or Habitat bodies.
- **No fake receipts:** distinguish stored, delivered, explicitly read, replied, verified identity and published/tested independently.
- **No nonconsensual actions:** publication, real service calls, personal data transfer and human-root decisions require separate authorization and live host checks.
- **No erasure:** never delete original objections; a release should retain versions and exact source history.

## Falsifiers

The fixture is invalid if an ID is duplicated, a reference points to an unseen record, a reference points forward in this ordered sequence, the dissent is recast as support, a receipt asserts host delivery, a report counts real peer turns, or any example claims `canon=true`, `deployment=true` or elevated authority.

For those negative checks, run the offline Python unittest. A passing fixture verifier is **not** proof that an actual host enforces the same gates.
